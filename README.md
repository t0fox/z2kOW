# z2kOW — z2k для OpenWrt

**z2kOW** — независимый порт и модификация [z2k](https://github.com/necronicle/z2k) для маршрутизаторов на OpenWrt. Проект сохраняет общую логику сетевых стратегий z2k, использует нативные механизмы OpenWrt и развивает собственные инструменты.

**Основное направление:** работа непосредственно на роутере **без обязательного VPS, удалённого relay или WARP**. WARP остаётся отдельной опциональной функцией, а не зависимостью установки, обновлений или остальных модулей. Общие механизмы z2k синхронизируются с upstream выборочно: изменения, относящиеся только к Keenetic или не подходящие OpenWrt, не переносятся автоматически.

> **Независимый проект.** z2kOW создаётся энтузиастом и не является официальным портом или частью команды z2k. Разработчики оригинального z2k не отвечают за изменения, релизы и поддержку z2kOW.

**Быстрые ссылки:** [Установка](#установка-и-релизы) · [Возможности](#особенности) · [Telegram](#telegram) · [Удаление](#удаление-z2kow) · [Документация](docs/README.md) · [Исходный код](https://github.com/t0fox/z2kOW)

## Назначение и границы

z2kOW — open-source программное обеспечение для обработки сетевого трафика и интеграции сетевых механизмов z2k с OpenWrt. Проект включает NFQUEUE-обработку, traffic classification, policy routing, локальные proxy/tunnel-компоненты, диагностику, WebPanel, обновление конфигурационных данных и платформенную автоматику.

Проект не является хостинговым VPN-, proxy- или иным сервисом доступа и не предоставляет пользователям внешний сетевой канал, учётную запись или гарантированный доступ к какому-либо стороннему ресурсу.

Оператор устройства самостоятельно отвечает за допустимость выбранной конфигурации и соблюдение применимого законодательства, правил сети и условий сторонних сервисов. Подробнее: [LEGAL.md](LEGAL.md).

## Что это

z2kOW объединяет **nfqws2, autocircular, пользовательские списки и диагностику** из z2k с OpenWrt-службами procd, fw4/nftables, UCI, ubus, netifd и dnsmasq. Работа с локальным трафиком и настройками не требует собственного VPS.

| Направление | Что входит |
|---|---|
| **Сетевые стратегии** | TCP/QUIC, autocircular, hostlist, свои списки, отдельные профили и пробы TCP16 |
| **Telegram** | Локальный прозрачный MTProto → WSS-прокси на Rust; семь архитектурных семейств в матрице сборки, статус альфа |
| **TikTok Fix** | Управление CDN-адресами через dnsmasq, проверка кандидатов и автоматическое переключение |
| **OpenWrt** | WebPanel, диагностика, FLOWOFFLOAD, установки и обновления подписанными архивами для нужной архитектуры |
| **Дополнительно** | RT proxy и необязательный WARP split-routing |

**Важно о статусе:** наличие функции в коде или успешный QEMU/CI-тест ещё не означает подтверждённую работоспособность на всех роутерах и у всех провайдеров. Особенности проверки Telegram описаны в [его контракте](docs/openwrt-telegram-contract.md).

## Особенности

### Собственные расширения z2kOW

- **TikTok Fix** — управление собственными DNS-подменами CDN-доменов `v77` и `v16`, поиск кандидатов, TLS-проверки, автоматический/ручной выбор и сохранение последнего успешного адреса. Существующие внешние DNS-подмены пользователя имеют приоритет.
- **Telegram для OpenWrt** — собственный локальный Rust transparent proxy и интеграция с nftables/procd вместо старого VPS-зависимого и Go-пути.
- **Selective FLOWOFFLOAD** — наблюдение и сравнение `none` / `software` / `hardware`; аппаратное ускорение зависит от драйвера и чипа.
- **Подписанный release lifecycle** — отдельные архитектурные архивы, проверки целостности и восстановление после неуспешной транзакции.

Это расширения **z2kOW**, а не обещание их наличия в оригинальном z2k. Upstream-функции по возможности остаются общими, чтобы не усложнять синхронизацию.

**Собственного DNS-менеджера в z2kOW больше нет.** В WebPanel отсутствуют DNS-раздел,
каталог резолверов, настройки DoH/DoT/DoQ/DNSCrypt и управление пакетом `dnsproxy`.
Для управления DNS можно самостоятельно установить AdGuard Home или другое
совместимое решение через OpenWrt. Системный `dnsmasq` и точечные DNS-подмены,
необходимые TikTok Fix и другим существующим механизмам маршрутизации, остаются.

При переходе со старой версии одноразовый скрипт **пытается** вернуть ранее
управляемые z2kOW настройки dnsmasq и снять собственное правило принудительного
DNS для LAN. При неоднозначном владении, пользовательских изменениях или ошибке
проверки DNS он сохраняет действующую конфигурацию; ручная проверка может
потребоваться. Ранее установленный `dnsproxy` автоматически не удаляется,
поскольку его могут использовать другие службы и клиенты сети.

### Сетевые стратегии

- Общий с upstream z2k генератор конфигурации nfqws2 и та же модель autocircular.
- Отдельные TCP-пулы с автоматической ротацией стратегий; внутренние upstream-имена сохранены для совместимости.
- Общий QUIC-пул для UDP/443 с отдельной детекцией прогресса QUIC.
- Отдельный **Discord voice/video** профиль для Discord/STUN UDP.
- Найденное состояние стратегий сохраняется между перезапусками.
- Hostlist-режим: выбранная обработка применяется к соответствующим доменным правилам, а не ко всему трафику подряд.
- Дополнительные пользовательские домены, whitelist и исключения.
- Автохостлист — nfqws2 может самостоятельно накопить домены, для которых требуется выбранная обработка.
- Пользовательские стратегии позволяют переопределить отдельный пул, не форкая всю конфигурацию.

### Списки пользовательских исключений

Файл `/etc/z2k/ipset/zapret-hosts-user-exclude.txt` принимает IP-адреса и подсети IPv4/IPv6, по одной записи на строку. Пустые строки и комментарии после `#` разрешены. Домены в этом файле не разрешаются в адреса и пропускаются с сообщением; для исключения домена используйте раздел «Исключения» в WebPanel или `lists/whitelist.txt`. Изменение через WebPanel применяется сразу, ручная правка файла — после перезапуска сервиса.

### OpenWrt-интеграция

- **procd** — управление основным сервисом, WebPanel и необходимыми локальными процессами;
- **fw4/nftables** — NFQUEUE, прозрачное перенаправление, метки и собственные правила;
- **netifd / ubus / UCI / hotplug** — интерфейсы, конфигурация, устройства и сетевые события;
- **cron** — обновление списков, диагностика и плановые проверки;
- **dnsmasq** — штатный механизм OpenWrt для локальных правил, используемых TikTok Fix;
- **`/etc/z2k`** — сохраняемые пользовательские данные, **`/usr/lib/z2k`** — файлы релиза, **`/tmp/z2k`** — временное состояние.

Отдельный Keenetic- или VPS-сервис на роутере для штатной работы не нужен.

### Сеть и прокси

- **Telegram** — прозрачная локальная обработка TCP-трафика Telegram для клиентов LAN: без ручного proxy, QR-кодов, URL-подписок и собственного VPS. Подробности и ограничения — [ниже](#telegram).
- **RT proxy** — отдельный компонент с нативным DNS/firewall-подключением и прямым резервным сетевым путём.
- **WARP** — **только по желанию пользователя**: выборочная маршрутизация IP/CIDR, доменов или устройств. Отсутствие WARP не должно отключать основные функции.
- **IPv4/IPv6** — по возможностям конкретных стратегий и OpenWrt-адаптеров.

Это локальные компоненты программного обеспечения, а не предоставляемый проектом публичный VPN/proxy-сервис.

### Инструменты и обслуживание

- **WebPanel** — статусы, режимы, сетевые стратегии, TikTok Fix, Telegram, WARP, диагностика и обновления.
- **`z2k diag` и `z2k-detect`** — системные проверки, сетевые пробы и диагностика соединений.
- **TCP16** — отдельная диагностика обрывов после первых 16–20 КБ.
- **Config validator / Blocked monitor** — проверка конфигурации перед применением и просмотр проблемных сессий.
- **Release manifest** — подписанные метаданные и проверка скачанного архива перед установкой.

## Установка и релизы

**Требования:** OpenWrt с системным пакетным менеджером `apk`, права `root`, доступ к источникам релиза и поддерживаемая архитектура. Доступные место и память установщик проверяет до изменений; на устройствах с небольшим объёмом RAM/flash установка может не пройти предварительную проверку.

Установка через SSH:

```sh
wget -qO- https://raw.githubusercontent.com/t0fox/z2kOW/main/scripts/openwrt/install.sh | sh
```

Если уже установлен `curl`:

```sh
curl -fsSL https://raw.githubusercontent.com/t0fox/z2kOW/main/scripts/openwrt/install.sh | sh
```

Bootstrap находится в `scripts/openwrt/install.sh`. Он ставит только необходимые **системные** APK-зависимости; сам z2kOW поставляется не набором APK, а **подписанным rootfs-архивом для архитектуры роутера**.

Текущая матрица архитектурных архивов: `arm64`, `arm`, `x86_64`, `x86`, `mips`, `mipsel`, `riscv64`. Для Telegram Rust в репозитории определены цели всех семи семейств в `platform/openwrt/tg-rust-targets.tsv`. Наличие цели сборки и бинарника не гарантирует совместимость с каждой моделью роутера и не заменяет проверку на устройстве.

При установке и обновлении: проверяется подпись `UPDATES.json`, выбирается и проверяется архив (размер и SHA-256), затем применяется общая транзакция `install_release(tag)`. Конфигурация и состояние отделены от заменяемых файлов. При ошибках предусмотрены откат и восстановление прерванной транзакции.

Подробнее: [операции с релизами](docs/openwrt-release-operations.md), [безопасность](SECURITY.md), [измерения архитектурных архивов](docs/openwrt-arch-artifacts-measurements.md).

### Windows: если сайты зависают

Если на iPhone или Mac сайты открываются, а на Windows-компьютере долго грузятся и падают, включите в Windows метки времени TCP. Откройте командную строку от имени администратора и выполните:

```cmd
netsh interface tcp set global timestamps=enabled
```

Вернуть как было:

```cmd
netsh interface tcp set global timestamps=disabled
```

Зачем это нужно: часть стратегий портит метку времени в поддельном пакете, чтобы сервер его отбросил. В Windows метки по умолчанию выключены, поэтому сервер принимает подделку, и соединение зависает. На iPhone и Mac метки включены, там всё работает. От блокировки по IP это не помогает.

Это настройка Windows-клиента, а не OpenWrt: z2kOW не может включить её на компьютере автоматически.

## Веб-панель

После установки:

```text
http://<адрес-роутера>:8088
```

В панели находятся состояние сервиса, стратегии, списки, TikTok Fix, Telegram, диагностика, FLOWOFFLOAD, необязательный WARP и управление обновлениями. Отдельного раздела DNS или управления DNS-серверами в z2kOW нет. Для функций, требующих системного пакета или бинарника, доступность определяется установленными компонентами и архитектурой устройства — не только наличием переключателя в интерфейсе.

**Панель предназначена для локальной сети.** Не открывайте её порт напрямую в интернет. Работа функций и их фактический статус должны проверяться отдельно от успешного отображения UI.

## Удаление z2kOW

**Не используйте `apk del` и не удаляйте каталоги вручную вместо деинсталлятора:** z2kOW ставится из подписанного архива и владеет не только файлами, но и службами, заданиями и сетевыми правилами.

Подключитесь к роутеру по SSH от `root` и выполните:

```sh
z2kow uninstall
```

Команда запрашивает подтверждение (допустимы `y`, `yes`, `да`; Enter и `n` отменяют операцию). Перед удалением сохраните необходимые настройки и пользовательские списки.

Деинсталлятор должен остановить службы, снять **принадлежащие z2kOW** задания cron, правила nftables, маршруты и локальные DNS-подмены TikTok Fix, восстановить ранее сохранённые настройки offload, удалить payload, пользовательскую конфигурацию, временные данные и метаданные отката. Для устаревших DNS-настроек предусмотрена осторожная очистка с проверкой владения; установленный отдельно DNS-сервер не удаляется. Чужие правила fw4, пакеты и настройки системы удалять нельзя.

**По умолчанию сохраняется регистрация WARP** — данные в `/etc/z2k/state/warp/` могут пригодиться при повторной установке. Если нужен полный сброс и деинсталлятор **завершился успешно**, удалите оставшийся каталог:

```sh
rm -rf /etc/z2k
```

Последняя команда необратима. **Если штатное удаление закончилось ошибкой, не выполняйте `rm -rf`**: сохранённые файлы могут потребоваться для безопасного повторного запуска деинсталлятора и очистки сетевых правил. Устраните причину ошибки и снова запустите `z2kow uninstall`.

Детали: [операции с релизами](docs/openwrt-release-operations.md).

## Как работает autocircular

z2k не требует вручную подбирать одну универсальную строку desync. У каждого пула есть набор стратегий: nfqws2 наблюдает новые соединения и при повторяющихся неудачах переключает стратегию для следующих соединений.

```text
новое соединение
      ↓
текущая стратегия пула
      ↓
наблюдение TCP / TLS / HTTP / QUIC
      ↓
успех ───────────────→ оставить стратегию
      ↓
повторяющиеся неудачи
      ↓
следующая стратегия
      ↓
состояние сохраняется
```

TCP, QUIC и Discord используют разные критерии прогресса. Обрыв на 16–20 КБ в эту ротацию не входит — для него существует отдельная система TCP16.

## Измерение и подбор сетевых стратегий

WebPanel может измерить сеть и подобрать отдельные стратегии для провайдера. Полный набор занимает в среднем около 20 минут и применяется только после успешных обязательных замеров.

Порядок внутренних пулов сохраняется совместимым с upstream. Некоторые probe-наборы используют внешние домены как технические тестовые цели; они нужны для воспроизводимости измерений и не являются обещанием доступности соответствующих сторонних сервисов.

## Отдельные профили трафика upstream

Некоторые upstream traffic classes используют отдельные TCP/UDP профили и тестовые идентификаторы.

### TCP/TLS traffic

Соответствующие доменные правила подключаются к общему hostlist + autocircular механизму.

### UDP traffic

Для голосовых и видеосессий используется отдельный `discord_udp` профиль:

- фильтрация идёт по сигнатурам `discord` и `stun`;
- охватываются Discord voice/STUN UDP-порты;
- используется отдельный набор fallback-стратегий;
- circular хранит общее состояние voice-пула, где обычно нет нормального hostname/SNI;
- desync применяется только к началу медиапотока, а не гонит весь высокобитрейтный звонок через NFQUEUE.

Это особенно важно для слабых роутеров: задача — повлиять на установление UDP-сессии, а не постоянно обрабатывать каждый пакет голоса или стрима.

В репозитории также сохранён upstream fallback:

```text
extras/discord-voice-hosts.txt
```

Это upstream-совместимый вспомогательный список; основной OpenWrt-путь — роутерный UDP-профиль.

## Telegram

Telegram в z2kOW — **локальный прозрачный MTProto → WSS-транспорт на Rust**, а не MTProxy с URL, секретом или QR-кодом. На устройствах в LAN не нужно включать прокси вручную: nftables перенаправляет выбранные Telegram TCP-соединения на локальный listener, сохраняет исходный адрес, а процессом управляет procd.

- **Никакого обязательного VPS, внешнего relay или WARP.** Legacy Go-клиент и старые VPS-настройки не являются частью текущего OpenWrt-транспорта.
- **Цели сборки Rust:** `arm64`, `arm` (ARMv5 soft-float), `x86_64`, `x86`, `mips`, `mipsel`, `riscv64`. Точное соответствие OpenWrt-архитектурам задаёт [`tg-rust-targets.tsv`](platform/openwrt/tg-rust-targets.tsv); работа конкретной сборки требует проверки на целевом оборудовании.
- **Режимы соединений:** Auto с программным лимитом 32 соединения или ручной лимит (в рамках ограничений RAM и файловых дескрипторов) через `/etc/z2k/tg-policy.conf`.
- **Граница протокола:** MTProto DC и media DC — целевой трафик Rust. Произвольный HTTP/CDN-трафик, включая TCP/80, нельзя отправлять в этот WebSocket-прокси.
- **Пользовательское выключение** не должно отменяться автоматическим восстановлением сервиса.

**Статус: альфа.** Часть проверок выполнялась в тестовой среде; полноценная приёмка на физическом OpenWrt и проверка реальных клиентов Android, iOS и Desktop ещё не завершены. Не следует считать успешный запуск или синтетический тест доказательством работы всех медиа-сценариев.

Технический контракт и ограничения: [Telegram для OpenWrt](docs/openwrt-telegram-contract.md).

## Обрыв на 16–20 КБ

Это отдельный механизм от autocircular.

Если соединение устанавливается, но передача обрывается после первых примерно 16 КБ, обычная ротация стратегий может не помочь. z2k использует отдельную пробу линии и карту сетей, чтобы подобрать подходящее имя для проблемных сетей.

На OpenWrt используются те же продуктовые сущности upstream:

- `z2k-tcp16-probe.sh` — измерение линии;
- `z2k-tcp16.lua` — runtime-подстановка;
- `tcp16_nets.txt` — карта сетей;
- persistent state — результат последнего измерения;
- ручной запуск через WebPanel;
- периодический запуск через OpenWrt scheduler.

## WARP — опциональная маршрутизация

WARP **не нужен для установки или штатной работы z2kOW**. Это дополнительная возможность для тех, кому требуется явно направлять **выбранный** IP/CIDR, домен, игровой список или LAN-устройство через Cloudflare WARP. Остальные соединения идут обычным маршрутом.

При включении отдельный движок `z2k-warpd` использует WireGuard/UDP либо запасной MASQUE CONNECT-IP через HTTP/2/TCP. OpenWrt-адаптер создаёт nftables mark, отдельную таблицу маршрутизации и правила **только для выбранного scope** и после подтверждения готовности туннеля. При отказе должен снимать маршрут (fail-open), а не оставлять трафик в blackhole.

Пользователь может настроить внешний proxy вручную, но **старые VPS-адреса и прокси не должны возвращаться как значение по умолчанию**. WARP и его регистрация изолированы от Telegram, TikTok Fix, системных DNS-настроек и базовых механизмов.

Подробнее: [контракт WARP](docs/openwrt-warp-contract.md).

## Обновления

**Единственный источник релизов для роутера — контролируемый и подписанный [`UPDATES.json`](UPDATES.json) z2kOW.** Устройство не должно скачивать обновления из манифеста оригинального z2k и не зависит от собственного VPS.

```text
изменение upstream z2k
         ↓
оценка применимости к OpenWrt
         ↓
адаптация и проверки z2kOW
         ↓
подписанный релиз для архитектуры устройства
         ↓
install_release(tag) → проверка → применение / откат
```

Новый upstream-тег сам по себе не запускает обновление: **Keenetic-only патчи можно признать неприменимыми** с сохранением записи в [реестре пропусков](docs/UPSTREAM-SKIPS.json). Общие возможности z2k сохраняют upstream-семантику там, где это оправдано, а функции z2kOW развиваются независимо.

Сборка публикует архитектурные архивы вместо обязательной доставки полного multi-architecture payload. `apk` остаётся менеджером только системных зависимостей. Установка, повторная установка и обновление используют один транзакционный путь; состояние релиза и пользовательские данные хранятся отдельно.

См. [политику upstream](UPSTREAM.md), [процесс публикации](RELEASING.md) и [операции с релизами](docs/openwrt-release-operations.md).

## Структура проекта

В репозитории разделены общий код z2k, OpenWrt-адаптеры, собственные функции и инфраструктура выпуска:

```text
z2kOW/
├── z2k.sh, lib/, files/       # общие механизмы и конфигурация z2k
├── webpanel/                  # интерфейс, API, страницы
├── platform/openwrt/          # procd, fw4/nftables, UCI, scheduler, CLI
│   ├── tg.sh, tg-proxy/       # прозрачный Rust Telegram и его адаптер
│   ├── tiktok.sh              # CDN / dnsmasq
│   ├── warp.sh, warp-domain.sh
│   ├── rt.sh, insta-ip.sh
│   ├── offload-observe.sh, offload-benchmark.sh
│   ├── uninstall.sh, release.sh, update.sh, retire-dns.sh
│   └── webpanel-brand/
├── scripts/openwrt/           # bootstrap, сборка, подпись, публикация
├── z2k-warpd/                 # отдельный опциональный WARP-движок
├── rt-proxy/                  # RT proxy
├── z2k-detect/, z2k-verify/
├── tests/                     # common, OpenWrt и WebPanel проверки (QEMU отдельно)
├── docs/                      # контракты, parity и документация
├── UPDATES.json
└── UPDATES.json.sig
```

Поддержка общей логики z2k — приоритет; **новые функции по возможности живут в OpenWrt-слое** и не должны превращаться в большой форк upstream, затрудняющий следующие обновления.

## Подпись обновлений

Production release metadata подписываются отдельным ключом z2kOW. Устройство проверяет подпись manifest и только после этого доверяет URL, размеру и SHA-256 release artifact.

Приватный production-ключ в репозитории не хранится.

Актуальный идентификатор ключа для производственного релиза записан в [`UPDATES.json`](UPDATES.json) (`signing.key_id`). Закреплённые публичные ключи установки хранятся в [`scripts/openwrt/release-keys/`](scripts/openwrt/release-keys/). Это позволяет проверять текущую цепочку доверия без устаревающего отпечатка в README.
