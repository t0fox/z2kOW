# Установка, обновление и восстановление z2kOW на OpenWrt

Это руководство для владельца роутера. Правила публикации для сопровождающих проекта — в [RELEASING.md](../RELEASING.md).

## Требования и ограничения

- права `root` и OpenWrt **24.10 или новее с `apk`** либо совместимый `SNAPSHOT`; `opkg`-only образ не подходит этому установщику;
- одна из архитектур `arm64`, `arm`, `x86_64`, `x86`, `mips`, `mipsel` или `riscv64`;
- доступ к HTTPS-источникам релиза и системным репозиториям OpenWrt;
- свободные память и место на постоянном разделе, которые установщик проверяет до внесения изменений.

**Важно:** семь поддерживаемых архитектур релиза не означают одинаковую доступность опциональных компонентов. Например, Telegram Rust поставляется только для `arm64` и `x86_64`.

Для проверок подписи bootstrap может установить через `apk` сертификаты CA, OpenSSL, JSON-инструменты и `curl`. Программа z2kOW устанавливается из подписанного rootfs-архива, **не** из отдельных APK.

## Установка

Подключитесь к роутеру через SSH от `root`:

~~~sh
wget -qO- https://raw.githubusercontent.com/t0fox/z2kOW/main/scripts/openwrt/install.sh | sh
~~~

Либо, если уже установлен `curl`:

~~~sh
curl -fsSL https://raw.githubusercontent.com/t0fox/z2kOW/main/scripts/openwrt/install.sh | sh
~~~

Bootstrap `scripts/openwrt/install.sh` проверяет совместимость и ресурсы, устанавливает нужные системные зависимости, получает контролируемый `UPDATES.json` и его подпись, проверяет Ed25519, выбирает **архив своей архитектуры**, проверяет размер и SHA-256, затем вызывает общую транзакцию `install_release(tag)`.

При загрузке и распаковке оцениваются **раздельные** потребности памяти и диска. Архив может размещаться на постоянном разделе, а не целиком в `/tmp`. При нехватке ресурсов установка должна завершаться до замены работающих служб.

## Управление установленной версией

~~~sh
z2kow status        # релиз и состояние
z2kow check         # доступное утверждённое обновление
z2kow update        # применить обновление
z2kow reinstall     # переустановить штатным путём
z2kow restart       # перезапустить основной сервис
~~~

Версия читается из `/etc/z2k/state/installed-release` и включает `tag + seq`. CLI, WebPanel, updater и диагностика должны использовать одну запись. Запущенный процесс сам по себе не является доказательством успешной установки.

Рядом хранится `installed-artifact-sha256` — квитанция о действительно применённом архиве. Это **не второй манифест**; она позволяет различить исправленный подписанный артефакт при неизменных `tag + seq`. При отсутствии квитанции механизм должен выполнить однократную полную установку проверенного релиза.

## Путь обновлений

Роутер использует **только** подписанный [`UPDATES.json`](../UPDATES.json) z2kOW. Обнаружение нового upstream-тега не публикует его автоматически. VPS, relay и WARP не являются обязательными каналами доставки. Обновление, ручная переустановка и первоначальная установка используют общий `install_release(tag)`.

Доставка — архитектурные архивы `openwrt-rootfs-<arch>.tar.gz`. Общий переходный `openwrt-rootfs.tar.gz` может существовать для совместимости со старым установленным загрузчиком, но не заменяет выбор ABI в новом пути.

## Владелец файлов и настроек

| Путь | Что хранится |
|---|---|
| `/etc/z2k` | Настройки, пользовательские списки, идентификаторы и постоянное состояние |
| `/usr/lib/z2k` | Заменяемый payload релиза |
| `/tmp/z2k` | Runtime-файлы и журналы |
| `platform/openwrt/owned-paths.txt` | Контракт владения дополнительными интеграционными файлами |

Системные LuCI/uhttpd, чужие firewall-правила, настройки DNS и другие пакеты не становятся собственностью z2kOW. Пользовательские данные сохраняются между обновлениями согласно контракту соответствующих функций.

## Сбой и восстановление

Перед заменой проверяются архитектура, пути, подпись и контрольные суммы, свободное место, необходимые пакеты и состояние старого релиза. Во время транзакции сохраняются прежние файлы; затем выполняются миграции, запуск и проверка служб. **Новая версия записывается только после успешного завершения проверок.**

При ошибке выполняется rollback. Если откат или проверка восстановленных служб не прошли, журнал и файлы восстановления сохраняются для повторной попытки. Временный загрузочный обработчик запускает восстановление из `/usr/lib/.z2k-install` **до запуска служб**, даже когда часть payload уже заменена.

Не удаляйте журнал восстановления вручную. Он не заменяет пользовательскую резервную копию конфигурации.

## Штатное удаление

z2kOW не устанавливается как APK, поэтому команда `apk del` не является способом удаления.

~~~sh
z2kow uninstall
~~~

Команда запрашивает подтверждение, останавливает сервисы, удаляет только принадлежащие z2kOW файлы, nftables/PBR, cron, hotplug и DNS-настройки, восстанавливает ранее изменённые параметры offload и удаляет пользовательскую конфигурацию. Чужие системные настройки и системные APK-пакеты массово не удаляются.

**По умолчанию сохраняется регистрация WARP** в `/etc/z2k/state/warp/`. Если требуется полностью стереть это состояние, **только после успешного сообщения о завершении** можно дополнительно выполнить:

~~~sh
rm -rf /etc/z2k
~~~

Если деинсталлятор завершился ошибкой, **не запускайте `rm -rf`**: устраните причину и повторите `z2kow uninstall`, чтобы очистить оставшиеся маршруты и правила безопасно.

## Диагностика и подтверждение

- Проверка CLI/панели не доказывает работоспособность dataplane.
- CI и QEMU полезны для проверки кода, отката, RAM и сетевого пути, но не гарантируют работу всех физических устройств.
- Для Telegram Rust необходима отдельная проверка [настоящих клиентов](openwrt-telegram-contract.md).
- Датированные замеры ресурсоёмкости приведены [отдельно](openwrt-arch-artifacts-measurements.md), а результаты проверки независимости от VPS — в [журнале](openwrt-vps-free-evidence.md).
