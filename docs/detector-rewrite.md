# Переработка детекторов — экспериментальная конфигурация

Изменение затрагивает два репозитория. Для выпуска нужны новое
`lua/zapret-auto.lua` из `zapret2-z2k` (коммит `bed207a`) и файлы z2k:
`z2k-alert.lua`, `z2k-quic-silence.lua`, `z2k-state-persist.lua`,
`z2k-modern-core.lua`, `strats_new2.txt`, `quic_strats.ini`, а также
обновлённый генератор `lib/config_official.sh`. После установки нужен перезапуск
nfqws2 и регенерация конфигурации. Формат `state.tsv` сохранён.

Не следует выпускать только обёртки со старым ядром: оно не поддерживает
нейтральный/отложенный результат и привязку к поколению. QUIC при отсутствии
нового API откатывается к штатным счётчикам, но это не эквивалент новой логики.
Сначала опубликуйте коммит движка в ветке, которую получает сборка z2k:
CI клонирует её для интеграционных тестов. Номера версий, теги и выпуск
этой переработкой не меняются.

Автоматические решения о ротации принимает только `circular`. Он закрепляет
стратегию за соединением, отделяет поколения, применяет кворум и терминальный
результат один раз. Слой persistence сохраняет решения, обрабатывает ручные
закрепления и сбрасывает отложенные записи таймером. Он не оценивает здоровье
сети для отмены решения ядра.

Проверки из каталога z2k:

```sh
Z2K_FORK_DIR=../zapret2-z2k-fork sh tests/run_all.sh
LUA=luajit sh tests/test_circular_core.sh
luajit tests/test_alert_detector.lua
luajit tests/test_http_classifier.lua
luajit tests/test_quic_silence_detector.lua
LUA=luajit sh tests/test_detector_persistence.sh
LUA=luajit sh tests/test_profile_observation.sh
```

Пакетные тесты исполняют настоящие Lua-библиотеку, `circular`, штатные и
кастомные детекторы. Таймеры, C conntrack и отправка пакетов моделируются.
Это проверка логики, а не реальная сетевая проба. Перед выпуском остаётся
проверить на роутере TCP/TLS и QUIC v1/v2 с реальным окном NFQUEUE,
ручное закрепление и восстановление `state.tsv` после перезапуска.

Ограничения: таймаут и ранний отказ не доказывают DPI; QUIC short-header
проверяется по наблюдаемым CID и форме пакета без расшифровки; при исчерпании
окна наблюдение нейтрально. Общий таймер ACKed ClientHello без ответа не добавлен;
узкое исключение для обновления Discord описано ниже.
Правила обрыва на 16 КБ не изменены.

## Экспериментальные параметры категорий

- TCP/HTTP: `retrans=2`, `fails=3`. Первый повтор не завершает попытку;
  второй может вызвать RST при включённом `Z2K_CIRCULAR_RESET`. Обычная
  потеря двух сегментов тоже может привести к неудаче: полевые проверки нужны.
- Discord UDP: `circular` видит оба направления и все типы пакетов внутри
  окна NFQUEUE. Фейки ограничены исходящими discovery/STUN в первых четырёх
  data-пакетах. Портовый диапазон согласован с NFQUEUE: 50000–50099.
- QUIC: `drop` ограничен исходящими Initial, которые заменяет `send`;
  ответы и последующий трафик не удаляются этим инстансом.
- TCP-фейки RKN №38 и YT/GV №18 получили `badsum`: уменьшение исходного TTL
  на единицу само по себе не обеспечивает отбрасывание фейка сервером.
- GV №11 теперь делает тот же разрез, что №6, но без sequence overlap.
  Остальные номера сохранены; перенумерации `state.tsv` нет.

Политика генератора явная: для TCP он нормализует `retrans/maxseq/inseq`,
набор детекторов и `reset`; для видео — также `time=300`. Она действует и на
`lists/custom-strategies/*.txt`, если там есть `circular`. Правка этих аргументов
в файле не переопределяет политику генератора. `Z2K_CIRCULAR_RESET=0` отключает
RST и для TLS, и для HTTP. Профиль без `circular` остаётся без автоподбора.

`nld=2` заменён полными именами. Только известный суффикс `.googlevideo.com`
объединяется для GV/QUIC/объединённого Google-пула; IP-семейства разделены.
Старые записи вида `googleapis.com|4`, включая frozen, не клонируются на все
API-поддомены. Они остаются на диске, но новые ключи поддоменов учатся заново;
нужные ручные закрепления следует повторить для конкретных имён. Записи
`googlevideo.com` сохраняют прежнюю область действия в GV/QUIC.

Окна NFQUEUE 20/10 TCP и 8/8 UDP не увеличены. На обычном MSS 1460 исходящий
порог успеха 32768 недостижим за 20 пакетов; это не обещание успеха по отправке,
а верхняя граница штатного наблюдения. Основной TCP-сигнал успеха остаётся
входящим. Глобально увеличивать нагрузку на очередь без замеров не стали.

## Эксперимент: зависшая проверка обновлений Discord

`Z2K_DISCORD_UPDATE_TLS_TIMEOUT=1` (умолчание) включает восстановление только
для точного имени `updates.discord.com`, TCP/443, в `rkn_tcp` с полным ключом
`z2k_service_hostkey`. Голосовой UDP-пул и остальные домены не меняются.
Выключатель `=0` сохраняется при регенерации конфига. `Z2K_CIRCULAR_RESET=0`
тоже полностью отключает это вмешательство.

От первого ClientHello отсчитываются 10 секунд. Таймаут учитывается только
если ClientHello целиком помещается в первую TLS-запись и подтверждён ACK,
но ответных данных не было. ACK должен нести ожидаемый TCP sequence сервера.
Любые входящие данные (даже первый байт разбитого TLS-ответа), FIN/RST,
дополнительный исходящий запрос или достижение границы перехвата отменяют
наблюдение. Неподтверждённый ClientHello остаётся штатному retrans-детектору.

Отказ передаётся через `circular_report_failure`: один раз на соединение,
с проверкой поколения, заморозки и обычным `fails=3`. После принятого отказа
клиент получает RST из заголовков последнего ACK сервера, чтобы приложение
могло создать новую попытку; уже открытый сокет не переводится на другую
стратегию. Переподключение зависит от поведения самого приложения.

На запись хоста/семейства допускается один ожидающий таймер и не более шести
принятых таймаутов в пятиминутном окне. После исчерпания бюджета новые
наблюдения допускаются только после конца окна и на новом ClientHello.
Бюджет переживает ротации стратегий, но хранится в памяти процесса.

Это восстановление зависшей попытки, а не доказательство DPI: действительно
медленный сервер тоже может получить повтор после 10 секунд. TLS-ответ,
который уже начался, этим механизмом не обрывается. Проверки моделируют C
conntrack, часы и отправку RST; реальную доставку RST и повтор запроса Discord
нужно проверить на роутере перед широким выпуском.
