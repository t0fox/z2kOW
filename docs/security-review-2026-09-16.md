## CodeQL: все десять предупреждений

| Alerts | Место | Вердикт |
| --- | --- | --- |
| [17](https://github.com/necronicle/z2k/security/code-scanning/17) | WARP H2, `tlsConfig` | Реальная ошибка: отсутствие/повреждение ключа пира отключало пиннинг. Исправлено локально: конфигурация отклоняется до соединения; ключ проверяется обязательным `VerifyConnection`. |
| 12–16 | Пять TLS-проб `z2k-detect` | Намеренная проверка проходимости, включая чужой SNI и прямой IP. Обычная проверка CA/имени изменит смысл измерений. Пробы не доказывают подлинность сайта и могут быть обмануты MITM. Оставлены без изменений. |
| 10 | `rt-proxy`, TLS health-пробы | Остаточный риск: без `--health-spki-pin` сервер не аутентифицируется. Подставной узел может пройти health-проверку. Пин по умолчанию пуст; наличие callback не делает проверку защищённой. Не закрепляли чужой ключ по недоверенному первому ответу. |
| 11 | `rt-proxy`, TLS к CONNECT-прокси | Внешний прокси не аутентифицируется. Пользовательский HTTPS проходит внутри него и проверяется клиентом. Сохраняются риски наблюдения метаданных/отказа, но отсюда не следует возможность расшифровать внутренний HTTPS. |
| 8–9 | WireGuard `SetMark`, `uint32` → `int` | Ложное срабатывание для этой операции: `unix.SetsockoptInt` затем преобразует значение в `int32` и передаёт ровно 4 байта. Все 32 бита метки сохраняются и на 32-битных платформах. Проверка `mark <= MaxInt32` сломала бы допустимые метки. |

Правило `go/disabled-certificate-check` ищет присваивание `InsecureSkipVerify=true`;
обязательный пользовательский пиннинг не гарантирует автоматического закрытия
alert 17. Правило не отключено, предупреждения через API не закрывались.
Для MASQUE системная CA-проверка не заменяет ключ из регистрации.

Если запись H2 уже не содержит корректного ключа пира, соединение теперь
завершается ошибкой с предложением обновить регистрацию MASQUE. Это намеренное
изменение: использовать такой туннель без проверки сервера небезопасно.
Обычный WireGuard и детекторы/таймер Discord не менялись.

## Gitleaks

Два точечных исключения в `.gitleaksignore` относятся только к конкретным
историческим fingerprints: искусственный ключ WARP+ из CGI-теста и пустое
присваивание Makefile, для которого regex захватил следующую строку GOFLAGS.
Новые ключи в тех же файлах не исключаются.

Повторный скан истории HEAD gitleaks 8.24.3 оставляет четыре находки:

- отдельный публичный токен `/resolve` в `z2k-insta-ip-refresh.sh`;
- один старый общий токен в трёх исторических местах: предыдущая версия того же
  скрипта, `cf-worker/wrangler.toml`, `mtproxy-client/main.go`.

Эти значения не скрывались allowlist. `/resolve` ограничен разрешёнными доменами,
но его токен нельзя считать конфиденциальным. Общий токен безопасно считать лишь
регистрационным купоном только при запрете старой авторизации на сервере:
`--v1-off` либо `--require-per-install`. Оба флага в исходниках по умолчанию false.
Нужно проверить действующее развёртывание и отозвать старый токен там, где он
ещё даёт доступ; удаление строки из репозитория этого не делает.

Скан всех локальных refs до исключений дал также две находки в коммитах вне
истории HEAD (`tg-proxy-win/main.go`, `REPAIR_PLAN_2026-06-10.md`). Их значения
не публикуются в отчёте; удалённые refs/настройки серверов не изменялись.
