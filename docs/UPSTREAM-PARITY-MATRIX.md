# Upstream parity matrix

This matrix compares the committed z2kOW source at `main` commit `2d8078b4083818415186309b5c98ccb443fc7523` with upstream `necronicle/z2k`, branch `z2k-enhanced`, tag `p-86.13`, sequence `136`, commit `7f630a9d459052b9c9c9eded06298f1b8f7f0a22`. The upstream revision was checked against the branch's current `UPDATES.json` on 2026-10-03. Upstream source paths below refer to that exact commit; z2kOW paths refer to the repository.

`PARITY` means the material behavior is shared. `ADAPTED` means the same purpose is implemented with an OpenWrt-native mechanism. `PARTIAL` means a material behavior or supported interface is absent or differs. `MISSING` means the upstream behavior has no implementation. `N/A` means the Keenetic-specific capability has no OpenWrt counterpart.

Evidence lists implementation sources and relevant suite names; it is not a report of test results or live-router acceptance.

| Feature | Upstream behavior | OpenWrt implementation | Status | Evidence |
|---|---|---|---|---|
| Fresh install | `z2k.sh` and `lib/install.sh` prepare paths, config, runtime, services, and install state. | `scripts/openwrt/install.sh` verifies the controlled manifest and complete rootfs, then invokes `install_release`; the release transaction stages and replaces owned paths. | ADAPTED | `scripts/openwrt/install.sh`, `platform/openwrt/release.sh`; `test_ow_installer.sh`, `test_ow_unified_release.sh` |
| Patch versus reinstall | `lib/auto_update.sh` applies history `patch` files and declared steps, or takes the `reinstall` path. | Both decisions install the complete signed rootfs. The OpenWrt path does not apply per-file patch steps or upstream `full_install` effects. | PARTIAL | `lib/auto_update.sh`, `platform/openwrt/release.sh`; `test_ow_unified_release.sh`, `test_ow_update_entry.sh` |
| Release authority and authenticity | Upstream `UPDATES.json` contains release history and is verified against its signing trust. | Root `UPDATES.json` is the sole device authority. Its Ed25519 signature binds artifact metadata; the artifact is checked by size and SHA-256 before extraction. | ADAPTED | `scripts/openwrt/install.sh`, `platform/openwrt/manifest.sh`, `scripts/openwrt/controlled_release.py`; signing and artifact suites |
| Repeat install and release state | The updater recognizes the installed tag and avoids reapplying an already-current release. | `/etc/z2k/state/installed-release` stores tag and sequence; a repeat is a no-op unless migration or legacy-state reconciliation is required. | ADAPTED | `platform/openwrt/release_state.sh`, `platform/openwrt/release.sh`; `test_ow_unified_release.sh`, `test_ow_updater_state.sh` |
| Failure recovery | Upstream snapshots patched files and rolls back failed update steps; reinstall has its own recovery behavior. | A write-ahead journal restores replaced product paths and release state after an ordinary transaction failure or detected interrupted transaction. | ADAPTED | `lib/auto_update.sh`, `platform/openwrt/release.sh`; `test_ow_recovery.sh`, `test_ow_unified_release.sh` |
| Config and strategy generation | Shared installer and config/strategy modules generate and validate runtime configuration while retaining supported user selections. | Shared z2k generator code is used with OpenWrt path and service adapters. Upstream per-file `steps` from release history are not run. | PARTIAL | `lib/config_official.sh`, `lib/strategies.sh`, `platform/openwrt/bootstrap.sh`; `test_ow_config_convergence.sh`, `test_ow_generate.sh` |
| Persistent config and user data | Configuration, custom lists, strategy state, and device data live outside replaceable code or are preserved by installer/update logic. | `/etc/z2k` holds config, state, relay identity, and user lists; the replaceable payload is rooted at `/usr/lib/z2k`. | ADAPTED | `platform/openwrt/paths.sh`, `platform/openwrt/owned-paths.txt`; `test_ow_paths.sh`, `test_ow_preserve.sh`, `test_ow_state_persist.sh` |
| Config backup and restore | Common menu/API supports operator backup and restore of configuration. | Shared backup/restore routines remain available with OpenWrt path mapping; the release journal is a separate transaction mechanism. | PARITY | `lib/config.sh`, `platform/openwrt/env.sh`; config and path suites |
| Legacy migrations | `lib/install.sh` migrates legacy layout, config, and state in ordered install steps. | OpenWrt migrates retired APK/feed ownership and relay identity; other upstream history steps are not interpreted by the full-payload installer. | PARTIAL | `platform/openwrt/release.sh`; `test_ow_unified_release.sh`, `test_ow_reinstall_guard.sh` |
| Architecture-specific runtime | Upstream selects architecture-specific runtime and helper binaries during install/update. | The complete artifact carries architecture variants; `platform/openwrt/arch.sh` maps OpenWrt target metadata and rejects unknown targets. | ADAPTED | `platform/openwrt/arch.sh`, `scripts/openwrt/stage-rootfs.sh`; `test_ow_arch.sh`, `test_ow_warp_archmap.sh` |
| Core process lifecycle | Upstream init and watchdog scripts own `nfqws2`, Telegram, RT, WARP, and scheduler processes on Keenetic. | procd owns OpenWrt service instances; fw4/netifd and hotplug own platform events. | ADAPTED | `platform/openwrt/files/etc/init.d/z2k`, `platform/openwrt/`; `test_ow_lifecycle.sh`, `test_ow_restart.sh`, feature lifecycle suites |
| Firewall and WAN integration | Upstream uses Keenetic NDM hooks, iptables/ipset, and NDM WAN/device policy signals. | OpenWrt uses owned nftables chains, fw4 includes, netifd/route detection, UCI, and hotplug. NDM policy behavior is not copied. | ADAPTED | `platform/openwrt/firewall.sh`, `lib/wan.sh`, `platform/openwrt/files/etc/hotplug.d/iface/90-z2k`; `test_ow_iface.sh`, `test_ow_fw_check.sh`, `test_ow_uci.sh` |
| Strategy engine and rotation state | Shared strategy pools and autocircular logic generate and retain per-host strategy state. | Common runtime and state logic remain in use; platform paths and startup ordering are supplied by OpenWrt adapters. | PARITY | `files/lua/`, `lib/strategies.sh`, `platform/openwrt/files/etc/init.d/z2k`; `test_ow_state_persist.sh`, shared strategy suites |
| Lists and periodic refresh | Upstream scheduled helpers refresh geosite, Telegram, WARP, and other lists using Keenetic storage and DNS APIs. | Shared fetch/filter logic is paired with OpenWrt-owned paths and system integration where provided. Any helper without an OpenWrt backend is a parity gap and must remain identified here. | PARTIAL | `files/z2k-update-lists.sh`, `platform/openwrt/schedule.sh`, `platform/openwrt/paths.sh`; `test_ow_schedule.sh`, list/geosite adapter suites |
| WebPanel service and shared pages | The common panel exposes service controls, strategy/config editing, user lists, update status, and diagnostics, with NDM-specific actions where available. | The common panel uses OpenWrt adapters, a separate procd service, and a capability response. LuCI/uhttpd remain outside z2kOW ownership. | ADAPTED | `webpanel/cgi/platform.sh`, `platform/openwrt/webpanel.sh`, `platform/openwrt/files/etc/init.d/z2k-webpanel`; WebPanel contract and suites |
| WebPanel capabilities | Upstream exposes TCP16, policy, PPE, uninstall, diagnostics, and other features according to platform support. | The committed OpenWrt capability response has TCP16, policy, PPE, fast route, and uninstall disabled; diagnostics, Telegram, and WARP are exposed, with custom DNS and offload conditional on prerequisites. | PARTIAL | `webpanel/cgi/platform.sh`, `docs/openwrt-webpanel-contract.md`; `test_ow_webpanel_cgi.sh`, `test_ow_webpanel_routes.sh` |
| TCP16 | Upstream has a TCP16 probe, configuration, and user-facing controls. | The common probe code exists, but the committed OpenWrt panel reports `tcp16:false`; it is not a supported OpenWrt control in this baseline. | PARTIAL | `files/z2k-tcp16-probe.sh`, `webpanel/cgi/platform.sh`; `test_ow_webpanel_cgi.sh`, TCP16 suites |
| Telegram transport | Upstream provides Telegram and CDN TCP transport with Keenetic redirect/firewall and service scripts. | OpenWrt uses a procd-owned client and nftables redirects/guards through the OpenWrt adapter. | ADAPTED | `platform/openwrt/tg.sh`, `platform/openwrt/files/etc/init.d/z2k`; `test_ow_tg_firewall.sh`, `test_ow_tg_lifecycle.sh` |
| RT proxy | Upstream uses Keenetic DNS overrides, redirect rules, and service lifecycle for RT traffic. | OpenWrt uses UCI host records, a local sentinel, nftables redirect rules, and procd. | ADAPTED | `platform/openwrt/rt.sh`, `platform/openwrt/files/etc/init.d/z2k`; `test_ow_rt_dns.sh`, `test_ow_rt_firewall.sh`, `test_ow_rt_lifecycle.sh` |
| WARP routing | Upstream uses WARP runtime, lists, NDM routing marks, and PPE controls. | OpenWrt uses a procd-owned WARP runtime, persistent device/list data, nftables marks, and conflict-checked policy routing. | Uninstall interface | Upstream exposes removal from its menu/installer, with an optional purge of user data. | A cleanup backend exists, but the committed `z2kow` CLI and WebPanel expose no uninstall action. `/etc/z2k` is preserved by release replacement; there is no supported operator uninstall command in this baseline. | PARTIAL | `platform/openwrt/uninstall.sh`, `platform/openwrt/z2kow.sh`, `webpanel/cgi/platform.sh`; `test_ow_product_cli.sh`, `test_ow_webpanel_cgi.sh` |
