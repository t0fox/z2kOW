# Соответствие z2kOW исходному z2k

Здесь отражены **актуальные различия архитектуры и поведения** по отношению к [necronicle/z2k](https://github.com/necronicle/z2k), а не список успешных тестов. Исторические подробные разборы перенесены в [архивный снимок матрицы от 12 октября 2026 года](archive/upstream-parity-matrix-snapshot-2026-10-12.md); старые коммиты, суммы, перечни изменённых файлов и сведения о проверках в нём сохранены без пересказа.

**Важно:** новое направление z2kOW — самостоятельная OpenWrt-адаптация с выборочным переносом upstream и собственными функциями. Работа на OpenWrt **не требует собственного VPS, удалённого relay или включённого WARP**. Унаследованные функции по возможности совпадают с upstream; отдельные расширения имеют свои контракты и оценки готовности.

## Как читать статусы

| Статус | Значение |
|---|---|
| `PARITY` | Общая логика и наблюдаемое поведение upstream сохранены. |
| `ADAPTED` | Назначение и семантика сохранены, системные операции реализованы через OpenWrt. |
| `PARTIAL` | Есть существенные отличия, недостающие действия или неподтверждённые сценарии. |
| `MISSING` | Для OpenWrt нет пригодной реализации требуемой функции. |
| `N/A` | Функция специфична для Keenetic и не имеет содержательного OpenWrt-эквивалента. |
| `z2kOW-only` | Собственное расширение, которое нельзя оценивать как копию upstream. |

Это **статус реализации**, а не гарантия работы на любой модели маршрутизатора. Тест на Linux/WSL, QEMU, синтетический сетевой smoke и приёмка на физическом устройстве — разные уровни подтверждения.

## Матрица функций

| Область | Требование / унаследованное поведение | Реализация на OpenWrt | Статус |
|---|---|---|---|
| Первичная установка | Настройка, runtime, службы и постоянные данные | Проверенный rootfs выбранного ABI через `install_release(tag)` | ADAPTED |
| Источник обновлений | Контролируемая история и версия | Только подписанный z2kOW `UPDATES.json`; upstream напрямую не используется | ADAPTED |
| Patch / reinstall | Миграции, сохранение и сброс согласно upstream | Одна транзакция; соответствие всех частных upstream-эффектов ещё требует проверки | PARTIAL |
| Учёт релиза | Одна версия для решения об обновлении | Канонические `tag + seq` и квитанция об установленном артефакте | ADAPTED |
| Восстановление | Не оставлять разрушенный релиз при ошибке | Журнал, rollback и восстановление при загрузке | ADAPTED |
| Пользовательские данные | Сохранение настроек, списков и идентификаторов | `/etc/z2k` независимо от заменяемого `/usr/lib/z2k` | ADAPTED |
| Стратегии и конфиг | Общая генерация nfqws2/autocircular | Общий код с тонкими платформенными адаптерами | PARITY |
| Жизненный цикл | Управление запуском служб | procd вместо Keenetic init/watchdog | ADAPTED |
| Firewall и WAN | Перехват, события сети, восстановление | fw4/nftables, UCI, ubus, netifd, hotplug и native WAN-probe | ADAPTED |
| Плановые задачи | Проверки обновлений, списков, TCP16 | OpenWrt cron; устаревшие задачи статистики удаляются | ADAPTED |
| DNS | Защита устройств LAN от подмены ответов на обычные UDP/TCP-запросы к внешним DNS | Отдельные fw4/nftables-правила перенаправляют запросы на dnsmasq; проверка резолвера снимает правила при отказе и возвращает их после восстановления | ADAPTED |
| Списки и geosite | Общие обновления и пользовательские исключения | Общая логика плюс адаптеры OpenWrt | ADAPTED |
| Отправка статистики | Удалена в `p-86.16` | Нет удалённого отправителя; `telemetry.tsv` остаётся локальным | PARITY |
| TCP16 | Проба, подбор, сохранение и применение | Lua, данные, планировщик, WebPanel и конфигурация OpenWrt | ADAPTED |
| Диагностика | Состояния службы, сети, firewall, стратегий | Общая структура с нативными проверками и логами OpenWrt | ADAPTED |
| Telegram | Передача Telegram через выделенный транспорт | **Собственный Rust MTProto → WSS без VPS**, только arm64/x86_64; статус **альфа**, приёмка не завершена | PARTIAL |
| RT proxy | Точные DNS-правила, локальный proxy и fallback | procd, dnsmasq/UCI, nftables, собственное восстановление | ADAPTED |
| WARP | Списки, выборочная маршрутизация, fail-open | Отдельный **опциональный** `z2k-warpd`, nft/PBR, без VPS по умолчанию | ADAPTED |
| Ускорение | Управление доступным сетевым ускорением | OpenWrt FLOWOFFLOAD; наличие hardware проверяется отдельно | ADAPTED |

## Что проверять при следующем изменении

1. Зафиксировать upstream тег, `seq`, commit и перечень файлов.
2. Оценить, какие изменения относятся к общей логике, а какие только к Keenetic, Entware или чужому VPS.
3. Не переносить upstream `UPDATES.json` и не менять подпись вне доверенного релизного процесса.
4. Проверить влияние на общие стратегии, обновления, сохранение данных и удаление.
5. Обновить статусы этой матрицы и [`UPSTREAM-SKIPS.json`](UPSTREAM-SKIPS.json), где применимо.
6. Раздельно зафиксировать исходные тесты, QEMU и приёмку на реальном роутере.
