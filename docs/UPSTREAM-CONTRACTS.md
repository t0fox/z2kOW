# Upstream contract audit: z2k → OpenWrt

Аудит выполнен 2026-09-27 по нормативным документам и исходникам
`necronicle/z2k` до последнего patch tag `p-86.1`
(`950928ee615431f3442640b08a9a1cb877641900`). Это upstream source-sync
граница в `tests/openwrt/BASELINE`, а не опубликованный OpenWrt release snapshot.
OpenWrt собирает адаптированный WARP runtime из `p-85.16`
(`2c1dc58d961e51d1845039c6741e4629f4e77be6`) только в repository CI;
подписанные Keenetic WARP-бинарники остаются на `r-85.12`
(`0cc9207fde8aa60ba0b170a918f66643af7e364b`). Опубликованный интеграционный
манифест и его подпись отдельно сохраняют ref из `MANIFEST_BASELINE`.
Эти три границы независимы и не должны называться одним «текущим payload».

Инвентарь behavioral/static suites, консолидации и mutation mapping см. в
[`docs/UPSTREAM-TEST-INVENTORY.md`](UPSTREAM-TEST-INVENTORY.md). Окончательные
сборки и Go-проверки выполняются только в repository CI.

В матрице 42 контракта. Статусы описывают смысл поведения, а не сходство
реализаций. Для `PARTIAL` указано, какое подтверждение отсутствует. CI PASS
не считается проверкой на реальном роутере, а проверка процесса — доказательством
прохождения пользовательского трафика.

Сводка классификации: 33 `OPENWRT-EQUIVALENT`, 1 `PARITY`, 2
`KEENETIC-ONLY / N/A`, 5 `PARTIAL`, 1 `STALE-DOC`; `MISSING` и `CONTRADICTED`
не осталось. Пять `PARTIAL` ждут только наблюдений на роутере или
целевого traffic/soak evidence; известного незакрытого source-level gap среди
них нет. Единственный `STALE-DOC` — upstream spec нового p-86 эксперимента,
чьи этапы расходятся с кодом и README; он не принадлежит адаптеру. `ACTION`
фиксирует выполненное исправление/слияние либо нужную документацию, не меняя
статус доказанности.
